# Worker startup validation

Cloudflare rejected the `video2ctx` API Worker with error 10021, "Script startup exceeded CPU time limit." Worker startup includes parsing the bundle and executing module-level initialization. Its one-second CPU limit is separate from request CPU limits.

The merged Settings PR (#75, main commit `d7cb89a`) changed no deployed API Worker source. The supplied deployment log confirms a Worker startup failure, but does not establish that the Settings rendering changes caused it. The Cloudflare-generated failure profile was not available locally.

## Fix

Load auth plugins, the Polar SDK, email rendering, and OpenAPI schema generation when their respective handlers need them. Wrangler still bundles the dependencies into the Worker; dynamic imports defer their initialization. Auth instances and SDK clients remain request-bound. There is no global cache of users, environments, contexts, or admin grants.

The first request using a deferred module pays its initialization cost; subsequent requests reuse the initialized module. This change does not eliminate that cost or claim faster cold authenticated requests.

## Measurements

Measured locally with Wrangler 4.120.0 on 2026-09-23, using the production minification setting and `--containers-rollout=none` to skip Docker image builds. No production upload or deployment was performed.

| Bundle | Active startup CPU | GC included in active CPU | Gzip bundle |
| --- | ---: | ---: | ---: |
| Main, minified | 259.6 ms | 102.9 ms | 1098.01 KiB |
| Deferred dependencies, run 1 | 158.5 ms | 28.9 ms | 1116.39 KiB |
| Deferred dependencies, run 2 | 132.0 ms | 29.0 ms | 1116.47 KiB |
| Deferred dependencies, run 3 | 109.5 ms | 27.7 ms | 1116.47 KiB |
| Deferred dependencies, CI command verification | 239.7 ms | 28.9 ms | 1116.47 KiB |

Local active CPU fell approximately 8-58%, with a median of 145.3 ms across the four final measurements. The wider range illustrates local scheduling and profiling variance; the GC reduction is more consistent. These are sampled local measurements, not Cloudflare deployment startup times. Run 1 preceded import-order formatting; the remaining measurements use the final source. The bundle grows slightly because deferring initialization introduces wrappers. Minification alone did not materially reduce startup CPU. Deferring auth alone also left the billing SDK reachable through an eager import, so both paths needed changing.

## Reproduce and guard

From `platform`, run `npm run check:startup`. This builds a dry-run minified bundle and writes `.wrangler/startup.cpuprofile`. It does not deploy. CI saves that profile as an artifact. The profiler is diagnostic, not an enforcement of Cloudflare's one-second validation limit.

`test/startup-loading.test.ts` verifies that importing the Worker entrypoint does not initialize these dependencies, that documentation loads on request, and that auth requests retain separate environments, execution contexts, and admin grants. Reintroducing an eager auth import was confirmed to fail this test. Existing auth, admin, billing, credit, email, and documentation tests cover behavior after initialization.

The final deployment must still pass Cloudflare's validation. If it fails, inspect the profile generated by that exact upload rather than treating local timings as proof of cloud acceptance.

References: [startup limits](https://developers.cloudflare.com/workers/platform/limits/#worker-startup-time), [validation errors](https://developers.cloudflare.com/workers/observability/errors/#validation-errors-10021).
