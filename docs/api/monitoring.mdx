Use the video2ctx API to check a YouTube channel, topic, or search on a schedule. Each check compares the leading video ID with the one seen on the previous check. Your application can read changes from the notification inbox.

## Monitor a channel for new uploads

This example checks the Google Developers channel once an hour. Set `VIDEO2CTX_API_KEY` as described in the [API quickstart](/api/quickstart), then create the monitor from your server or terminal.

```bash
curl 'https://api.video2ctx.dev/v1/monitors' \
  --header "Authorization: Bearer $VIDEO2CTX_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{
    "provider": "youtube",
    "kind": "channel",
    "target": "UC_x5XG1OV2P6uZZ5FSM9Ttw",
    "intervalMinutes": 60
  }'
```

Save the monitor ID from the response. The default interval is 24 hours. Supported intervals in minutes are 60, 360, 720, 1440, 4320, and 10080.

## Read new-video alerts

For example, suppose the first check sees video A. It saves A as the baseline and sends no alert. If the channel uploads video B before the next hourly check, that check sees B and creates an inbox notification when in-app alerts are enabled (the default). If several videos arrive between checks, the monitor observes only the newest one.

```bash
curl 'https://api.video2ctx.dev/v1/notifications' \
  --header "Authorization: Bearer $VIDEO2CTX_API_KEY"
```

Use `POST /v1/notifications/{id}/read` to mark a notification as read. For email alerts, the account owner must [enable and confirm email delivery](/dashboard/notifications).

## Manage a schedule

- [List monitors](/api-reference/monitoring/list-monitors) with `GET /v1/monitors` to check their state.
- `PATCH /v1/monitors/{id}` to change query metadata, interval, or enabled state.
- `DELETE /v1/monitors/{id}` to stop and remove a monitor.
- `GET` and `PUT /v1/notification-preferences` to control channels.
